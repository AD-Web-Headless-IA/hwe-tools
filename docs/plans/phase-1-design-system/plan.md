# Phase 1 — Design System (`@hwp/core-ui`)

> Living document. Source plan for `/plan-to-stories` when we are ready to generate the formal US backlog.
> This file is **methodology only** — generic across all clients. Per-source classification work lives under `sources/`.

## Goal

Build the reusable design system for HWP — atomic blocks, page templates, and the composition pattern for client sites.

The design system is fed by **visual references** imported via `/import-figma` into `figma-makes/{slug}/`. Each reference is a Figma Make export from one real client; together they inform what is generic enough to belong in `@hwp/core-ui` and what is specific to a single client.

## Approach

**Module-by-module, collaboratively.** No bulk decisions, no assumptions.

For each module identified in a visual reference, we go through this loop:

1. **Propose** — Claude proposes a classification:
   - `Atomic Block` → `@hwp/core-ui/base-blocks/` — small, self-contained, reusable across many pages and clients. (DEC-015: formerly `blocks/`)
   - `Page Template` → `@hwp/core-ui/templates/` — full page layout reused with different data (e.g. `AccommodationDetailTemplate`).
   - `Client Composition` → `apps/site-{slug}/` — specific assembly of blocks and content for one client, not reusable.
2. **Discuss** — tradeoffs: reusability vs specificity, customization surface, performance, accessibility. **Also discuss: does this block need slots?** If clients are likely to want to inject content into it (e.g. a seasonal badge, a trust badge after the CTA), declare a `.slots.ts` file as part of the base-block. Add a "Slots?" column to the Classified table row.
3. **Decide** — log the decision in the **Classified** table below with rationale.
4. **Build** — only after classification is final. TDD: tests first.

> **Slots? column:** when filling in the Classified table, add a `Slots?` column. Possible values: `Yes — {slot names}` / `No` / `TBD`. A slot is warranted when at least one client is expected to want to inject content at a specific point in the block without fully overriding its DOM structure.

A module's classification is decided **once** for the design system. If a second source surfaces the same module (e.g. another client also has a "Hero with booking bar"), we revisit the existing decision rather than re-classifying — the table is the source of truth.
