# US-001 — Implement GalleryBlock (+ SwiperPrimitive)

> **Epic:** base-blocks · **Status:** Done (closed 2026-06-19 — `/verify` green: typecheck · test 213 · lint · build) · **Source:** `hwe-tools/docs/guides/guia-galleryblock.md`

## Description

Reusable image gallery block for hospitality sites — used on nearly every page (accommodation, services, activities, surroundings). Carousel variants are powered by **Swiper.js** (React components); static variants by **CSS Grid**. The lightbox is built with Swiper (fullscreen + zoom), with no external lightbox dependency.

This story delivers **two units**:

1. **`SwiperPrimitive`** — a reusable Swiper wrapper in `packages/core-ui/src/primitives/Swiper/`. Not a block: a primitive that any block can consume so Swiper is never imported directly elsewhere. Its platform-wide contract is now ratified by **[DEC-028](../../../architecture/decisions.md)** — follow that contract (single import site, `'use client'`, ARIA wiring, required `ariaLabel`, token-driven visuals, modular imports).
2. **`GalleryBlock`** — the gallery block in `packages/core-ui/src/base-blocks/GalleryBlock/`, consuming `SwiperPrimitive` for its carousel variants.

> **Two firsts for the codebase.** GalleryBlock is the first block to (a) use the **Layer-3 behavioral config schema** (`*.config.schema.ts`, defined in the contract but unused so far) and (b) use the **DEC-008 structural-variant layout** (`index.ts` resolver + one subfolder per variant — no block uses it yet). Treat the contract as the source of truth, not the existing flat blocks (HeroBlock currently ships without a co-located schema — that is a known outlier, not the pattern to copy).

## Visual variants (structural — DEC-008)

Per `decisions.md` DEC-008, GalleryBlock is the canonical example of **structural variants**: each variant has divergent DOM and hooks, so each is its own subfolder resolved by `index.ts` — **not** a CVA recipe. (A CVA `tone`/styling variant *inside* a given variant is fine; the structural choice is not.)

| Variant | Engine | Swiper modules | When to use |
|---|---|---|---|
| `slider` | SwiperPrimitive | Navigation, Pagination, Autoplay (opt.), A11y, EffectFade (if `effect: 'fade'`) | General galleries, rotating banners — images one at a time |
| `slider-thumbs` | SwiperPrimitive (2 synced instances) | Navigation, Thumbs, A11y | Accommodation/service detail pages (most common in hospitality) |
| `grid` | CSS Grid | — | Show all photos at once (facilities, activities) |
| `masonry` | **CSS columns** | — | Variable-ratio photos, "discover the area" pages. Use CSS `columns` (not Grid `masonry`, not JS) — see resolved decision #2. |
| `collage` | CSS Grid areas | — | Editorial header: one featured image + smaller ones |

**Lightbox (cross-cutting, all variants):** Swiper fullscreen instance (Zoom + Navigation + Keyboard + A11y) — swipe/pinch, ←/→/Esc, visible caption, fade backdrop, focus trap. Disabled via config `lightbox: false`.

Separate Zod schema for behavioral options (NOT content):

| Field | Type | Default | Applies to | Notes |
|---|---|---|---|---|

## Functional requirements

### SEO (non-negotiable)
- All images via `next/image` (never `<img>`); `alt` enforced by Zod.
- First image visible in the initial viewport gets `priority={true}` (LCP). For `slider`/`slider-thumbs`: first slide. For `grid`/`masonry`/`collage`: the ~3–4 above-the-fold images.
- Captioned images wrapped in `<figure>` + `<figcaption>`.
- JSON-LD `ImageGallery` (with `ImageObject[]`) — **server-rendered** (see boundary requirement).
- Heading hierarchy: if `title` is present, render at the `headingLevel` config value (default `2`), never hardcoded and never `<h1>`.

### Accessibility (non-negotiable)
- WAI-ARIA [Carousel Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/): container `role="region"` + `aria-roledescription="carousel"` + `aria-label`; each slide `role="group"` + `aria-roledescription="slide"` + `aria-label="Image X of Y"`.
- Keyboard: ←/→ navigate, Enter/Space open lightbox, Esc close, Tab between controls.
- Lightbox: focus trap on open, restore focus on close, `role="dialog"`, `aria-modal="true"`, images keep their `alt`.
- `prefers-reduced-motion`: disable autoplay, reduce slide/lightbox transitions to instant.

### Performance
- Lazy loading via `next/image` for every image except the first visible one (critical for `grid`/`masonry` with 20+ images).
- Import only the Swiper modules the active variant needs (tree-shaking); `grid`/`masonry`/`collage` load **no** Swiper.
- Modular Swiper CSS imports (`swiper/css`, `swiper/css/navigation`, …), never the full bundle.

### Server/client boundary (SEO + interactivity)
Split the block so SEO content is server-rendered and only interactivity is client-side:
- **Server shell** (RSC, no `'use client'`): parses content+config schemas, renders the semantic `<figure>`/`<img>` (via `next/image`) markup and the JSON-LD `<script type="application/ld+json">`. This guarantees images, `alt`, and structured data exist in the SSR HTML.
- **Client island** (`'use client'`): hydrates the carousel/lightbox interactivity over the server-rendered markup.

Rationale: the `seo-audit-geo-llm` audit performs an SSR check; injecting JSON-LD/images only from a client component fails it.

## Styling
- Carousel controls derive from theme tokens: arrows `var(--color-on-surface)` on `var(--color-surface/80%)`; active dot `var(--color-primary)`; inactive dot `var(--color-on-surface/30%)`; lightbox backdrop `rgba(0,0,0,0.9)`.
- **Zero CSS per block** — Tailwind utilities + theme tokens + Swiper's own base CSS only.
- Client overrides scope: `[data-block="gallery"]` (in the client repo's dedicated CSS file, never `globals.css`).

## Resolved decisions

1. **SwiperPrimitive → ratified as [DEC-028](../../../architecture/decisions.md) (Accepted, 2026-06-19).** It is a shared carousel primitive that 5+ blocks (Gallery, Reviews, AccommodationCard, Promo, footer logo slider) will depend on, so it carries a formal contract: single import site at `primitives/Swiper/`, `'use client'`, encapsulated ARIA carousel wiring + keyboard + `prefers-reduced-motion`, required `ariaLabel`, token-driven visuals, modular Swiper imports, `swiper` added to `core-ui` deps. GalleryBlock is its first consumer and API reference. Implement against the DEC-028 contract — do not set the primitive's API implicitly.
2. **`masonry` technique → CSS `columns`.** Decided: use CSS multi-column layout. CSS Grid `masonry` lacks universal browser support yet, and a JS masonry library is overkill for this. Note the known trade-off: `columns` lays out top-to-bottom per column, so DOM/reading order differs from visual left-to-right order — keep the source order meaningful and verify with the a11y test.
3. **Heading level → explicit `headingLevel` prop (`2 | 3 | 4`, default `2`).** Decided: the level is an explicit config field, not inferred from composition context — more predictable across pages. Lives in `GalleryBlock.config.schema.ts`. Never `<h1>`.
