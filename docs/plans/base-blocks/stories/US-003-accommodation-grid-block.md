# US-003 — Implement AccommodationGridBlock (+ AccommodationCard + booking deep-link port)

> **Epic:** base-blocks · **Status:** Draft (awaiting team review) · **Source:** designer references (room-listing carousel + "Nos Résidences" feature cards) + existing orphan schema `schemas/AccommodationGridBlock.schema.ts` + figma `figma-makes/site-demo/src/app/components/AccommodationCard.tsx`
> **Generated by** `/generate-block-story`. Paths are relative to the **hwe-core repo root** (base blocks live in `@hwe/core-ui`); architecture/contract/spec docs live under the mounted `hwe-tools/` submodule.

## Description

A content-driven (PayloadCMS-authored) block that presents a set of accommodation options as cards — each with a cover image, optional badge/category, title, key specs (capacity, surface) and/or icon features, an optional starting price, and a CTA. The CTA points **either** to an internal accommodation detail page **or** to the booking engine pre-filtered by an accommodation category (engine-agnostic deep link). The block is the rich, semantic counterpart to the image-only `GalleryBlock` currently used as a stopgap for this exact section in `site-demo`.

This story delivers **three units** (like US-001 delivered `SwiperPrimitive` + `GalleryBlock`):

1. **`AccommodationCard`** — a presentational sub-component (not a registered block) in `packages/core-ui/src/base-blocks/AccommodationGridBlock/AccommodationCard/`. Renders one accommodation. Reuses the existing primitives `Icon` (DEC-024), `Button`, `Eyebrow`. Has internal visual variants (see below).
2. **`AccommodationGridBlock`** — the collection block in `packages/core-ui/src/base-blocks/AccommodationGridBlock/`, consuming `AccommodationCard`. Owns the section heading/eyebrow, the structural layout (grid / slider / category sections), optional category filtering, and the JSON-LD. **Completes the orphan schema** that already exists at `schemas/AccommodationGridBlock.schema.ts` (extended — see below), so it is registered and demoed for the first time.
3. **`createBookingLink` adapter port** — a new engine-agnostic capability under `packages/core-ui/src/adapters/booking/` that builds a deep-link URL to the booking engine for a given accommodation category, resolved from the tenant's engine via a registry (DEC-025). No `if (engine === 'x')` in block code.

### Naming & "am I stepping on something?" — resolved

- `schemas/AccommodationGridBlock.schema.ts` is today an **orphan schema only**: its sole references are the file itself and its re-export in `schemas/index.ts`. There is **no component, no variants, no test, no `baseBlockRegistry` entry, no `site-demo` usage**. It exists because `AccommodationGridBlock` is the **canonical documentation example** in `block-architecture.md` (structured-data table) and `coding-standards.md` (generic-names rule). This story **implements** that intended block — it does not collide with anything functional.
- `GalleryBlock`'s guide reserved the name `AccommodationCardBlock` for the *detail-page photo gallery* (a `slider-thumbs` of one accommodation's photos). That is a **different** concern. To avoid the clash we keep the established name **`AccommodationGridBlock`** for this listing block, and `AccommodationCard` for the sub-component. A future per-accommodation photo gallery remains a GalleryBlock `slider-thumbs` usage, not this block.
- **Relationship to GalleryBlock:** `site-demo`'s `AccommodationComposition` currently fakes the "Explore other accommodations" listing with a `GalleryBlock` slider — a stopgap that shows images+captions only (no specs, no per-category booking CTA). This block replaces that stopgap. The two combine by **sharing `SwiperPrimitive`** (the carousel primitive, DEC-028), never by nesting GalleryBlock inside.

## Visual variants

### Block structural variants (DEC-008 — `index.ts` resolver, one subfolder each)

| Variant | DOM/engine | When to use |
|---|---|---|
| `grid` | CSS Grid, responsive `1 → 2 → columns` | Default listing — show all accommodations at once (the "Nos Résidences" 3-up reference). |
| `slider` | `SwiperPrimitive` (DEC-028), `slidesPerView` responsive ramp | Horizontal carousel of cards (the room-listing reference: 4 cards, arrows). |
| `sections` | one titled `<section>` per category, each rendering a `grid` of its items | Grouped-by-category page (e.g. *Chambres* then *Appartements*). |

These are **structural** (divergent DOM + hooks → subfolders + resolver per DEC-008), exactly like GalleryBlock. Category **filtering** (tabs) is an additive behavior on `grid`/`slider` (config `categoryFilter: 'tabs'`); the `sections` variant groups instead of filtering. Together these cover the three category arrangements requested.

### Card visual variants (internal to `AccommodationCard`, selected by config `cardVariant`)

| Card variant | Layout | Matches |
|---|---|---|
| `overlay-stats` | Title + category **overlaid** on image (bottom gradient), optional corner badge; compact KPI stat row (surface · capacity); full-width solid CTA bar. | Room-listing reference (CHAMBRE 2 · 22M² · 2 PERS · "VOIR LA CHAMBRE"). |
| `overlay-features` | Title (+ optional location with `map-pin`) overlaid; 2-column icon+label feature list; text-link CTA with trailing arrow. | "Nos Résidences" reference (PARIS 8 · 24 STUDIOS · ROOFTOP · "DÉCOUVRIR ↗"). |
| `stacked` | Image on top (no overlay); name, description paragraph, metadata row, link CTA. Neutral default. | Existing figma `AccommodationCard.tsx`. |

The card is a sub-component, so it may switch on `cardVariant` with small per-variant components in `AccommodationCard/variants/` (the DEC-008 subfolder rule formally governs *blocks*; the card stays cohesive within the block folder).

| `description` | string | no | Short paragraph (used by `stacked`; optional in overlay variants). **Relaxed** to optional — the overlay references show no paragraph. |
| `badge` | string | no | Corner badge (e.g. "02", "A1"). |
| `category` | `{ id?: string; label: string }` | no | `label` → eyebrow on the card + grouping/filter key; `id` → booking category for the deep-link CTA. |
| `location` | string | no | Sub-label with `map-pin` icon (e.g. "Hauts-de-Seine"). |
| `capacity` | number (int > 0) | no | Guests. Feeds JSON-LD `occupancy`. **Relaxed** to optional (residence cards may not state it). |

| `priceFrom` | string | no | e.g. "350 €/sem.". Feeds JSON-LD `offers`. |

**`AccommodationFeature` (nested):** `{ icon: string; label: string }` — `icon` is an `Icon` registry name (DEC-024).

**`AccommodationCta` (discriminated union on `kind`):**

| `kind` | Fields | Behavior |
|---|---|---|
| `'page'` | `href: string`, `label?: string` | Internal link to the accommodation detail page (`<a href>` via `Button`). |
| `'booking'` | `categoryId: string`, `label?: string` | Deep link to the booking engine for that category, URL built at render by `createBookingLink(tenantBooking, { categoryId })` (the adapter port). |

> Migration note: the existing `detailsHref?: string` is superseded by `cta: { kind: 'page', href }`. Keep `detailsHref` as an accepted alias for one cycle (Zod `.transform` to the union) if any consumer relies on it; otherwise remove and update the schema's only re-export.

## The booking deep-link port (DEC-025)

A new, small adapter family mirroring the existing search/favorites/simpleblock ports — but **pure** (returns a URL string, no DOM, no script):

- `adapters/booking/link/types.ts` — `BookingLinkBuilder = (booking: TenantBookingConfig, params: { categoryId: string; locale?: string }) => string | null` and a factory type.
- `adapters/booking/link/registry.ts` — `resolveBookingLinkBuilder(engine)` map (DEC-025; never branch on engine in block code). Returns `null`/throws-gracefully for engines without a known URL scheme.
- `adapters/booking/link/{thr,mastercamping}/` — per-engine builders. THR categories are numeric ids (see `BookingSimpleBlock.schema.ts` `categories`); Mastercamping uses `bookingUrl` + `idProperty` (see `client.config.ts`). The exact query-param scheme per engine is an **open question** (see below) — implement THR first, leave others as `notImplemented` placeholders (registry precedent).

The block reads the tenant booking config the same way the other booking blocks do (`TenantConfig.booking`, DEC-025). When the engine has no link builder, a `'booking'` CTA degrades gracefully (renders disabled or falls back to a configured generic booking URL) — never crashes.

## Functional requirements

### SEO (non-negotiable)
- All images via `next/image` (never `<img>`); `alt` enforced by Zod; `width`/`height` required (CLS).
- The first row of cards above the fold gets `priority` on their images (LCP); the rest lazy-load.
- Cards rendered as a list: `<ul>`/`<li>` (or `<section>` + repeated `<article>`) with the heading at `headingLevel`.
- **JSON-LD `ItemList`** with `itemListElement[]`, each item an `Accommodation` (schema.org) carrying `name`, `description`, `occupancy` (from `capacity`), `floorSize` (from `surface`), and `offers` (from `priceFrom`). **Server-rendered** (same boundary requirement as GalleryBlock — the geo-llm audit checks SSR).
  - ⚠️ `block-architecture.md` §392 currently lists `AccommodationGridBlock → ItemList → LodgingReservation`. `LodgingReservation` models a *booking*, not a *listing item* — `Accommodation`/`HotelRoom`/`Apartment` is the correct per-item type. **Reconcile the spec table during `/archive`** (flag, don't silently diverge).
- Heading hierarchy respected; never `<h1>` inside the block.

### Accessibility (non-negotiable)
- `slider` variant: WAI-ARIA [Carousel Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/) — delivered through `SwiperPrimitive` (it owns the ARIA wiring per DEC-028; pass a required `ariaLabel`).
- `categoryFilter: 'tabs'`: WAI-ARIA [Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) (`role="tablist"`/`tab`/`tabpanel`, arrow-key navigation) — or a filter `<fieldset>` of toggle buttons with `aria-pressed`; pick one and test it.
- Each card is an `<article>`; the CTA is a real link/button (`Button` primitive) with an accessible name (never a bare arrow icon — the arrow is `aria-hidden`, the link text carries the label, including the accommodation name for context, e.g. "Discover Paris 8").
- Decorative/feature icons are `aria-hidden` (the `Icon` primitive does this when no `label` is passed); the adjacent text is the accessible content.
- `prefers-reduced-motion`: carousel autoplay/transitions reduced (handled by `SwiperPrimitive`).
- `toHaveNoViolations` (vitest-axe) for every variant and for the filtered state.

### Performance
- `next/image` lazy-loading for below-the-fold cards; `priority` only above the fold.
- `slider` imports only the Swiper modules it needs **via `SwiperPrimitive`** — never import `swiper` directly.
- `grid`/`sections` load **no** Swiper.
- `createBookingLink` is pure and tree-shakeable; the booking engine's *script* is **not** loaded by this block (deep link only).

## Styling
- Zero CSS per block — Tailwind utilities + theme tokens only. No hardcoded colors/spacing.
- Overlay gradient, badge, CTA bar, eyebrow, feature icons all derive from tokens (`--color-primary`, `--color-accent`, `--color-on-surface`, `--color-surface`, `--tracking-eyebrow`). The block ships **token-neutral** (platform base block) — per-client look comes from that client's tokens / Level 2-3 overrides (GalleryBlock precedent, Cristina 2026-06-19).
- The references' magenta/navy/gold palettes are **client tokens**, not block CSS.
