## Notes for @hwp/core-ui
- Stack: **Vite + react-router SPA** (not Next.js), Tailwind v4, shadcn/ui, pnpm. HWP target is Next.js — port the composition pattern, not the routing.
- Tokens are already **semantic + brand split** (shadcn style) — best match yet to the HWP `TokensContract`. Good canonical base for future clients.
- **Zero border-radius on all block-level components** — cards, CTAs, image containers. The `--radius` token is for shadcn primitives only; block components intentionally use square corners.
- **Card style: shadow not border** — `box-shadow: 0 2px 20px rgba(26,74,82,0.09)` (soft teal-tinted). No border on card containers. Background is `bg-card` (white).
- **Eyebrow pattern**: `text-xs uppercase tracking-[0.2em] text-accent` always precedes h2; `w-16 h-0.5 bg-accent` divider bar follows h2 *only* in MediaTextBlock, not standalone section headings.
- `MediaTextBlock` is the exemplar prop-driven block (5 instances across 2 pages); `AccommodationGrid` and `ImgGallerySection` follow the same prop-driven shape. Prioritize these for `@hwp/core-ui/base-blocks/`.
- Self-contained blocks (Hero, BookingWidget, AmenitiesGrid, ReviewGrid, Nav, Footer) hard-code content — must be refactored to content-schema driven before entering core-ui (multi-tenant rule).
- `LeCampingPage` has inline page-hero + intro-split sections not yet componentized — classify in Phase 1 (block vs composition).
- See `./design-language.md` for full visual pattern catalogue (card style, spacing, typography hierarchy, interaction style).
